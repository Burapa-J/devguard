ทำไมต้องใช้ devguard? Why devguard?

แก้ 2 ปัญหาใหญ่ของการใช้ AI เขียนโค้ด: (1) AI ชอบสรุปว่าเสร็จทั้งที่โค้ดยังรันไม่ผ่าน และ (2) เปลือง Token ไปกับการอ่านไฟล์ซ้ำและ log ยาวเหยียด Solves the two biggest failure modes of AI coding agents: (1) unverified "done" claims and (2) context windows bloated by raw shell output and blind file searches.

🛡️ ชั้นที่ 1: Evidence-First Working ModeLayer 1: Evidence-First Working Mode

  • โหมดอ่านอย่างเดียวเมื่อถามคำถาม: เมื่อคุณถามหรือปรึกษาแนวทาง AI จะไม่แอบแก้ไฟล์จนกว่าคุณจะสั่งให้ลงมือ Read-only on questions & plans: Discussing options or asking "should we do X or Y?" never mutates files until you ask to implement.
  • เลือก Playbook ตามงาน: แยกขั้นตอนชัดเจนสำหรับ Investigation, Bug fix, Feature, Refactor, Perf และ LLM Pipeline Task-specific playbooks: Dedicated workflows for Investigation, Bug fix, Feature, Refactor, Perf, and Prompt/LLM evals.
  • ต้องมีหลักฐานจริงจาก agent-verify: บันทึกผลรันและ exit code ลง .verify/<name>.log พร้อมชี้บรรทัดที่พัง (errors_at=L...) Mandatory runtime proof via agent-verify: Captures full output to .verify/<name>.log and pinpoints failing lines (errors_at=L...).

⚡ ชั้นที่ 2: ประหยัด Token แบบไม่ทำลายหลักฐานLayer 2: Lossless Token Efficiency

  • บีบอัด Shell Output ด้วย rtk: ลดขนาดผลลัพธ์คำสั่งทั่วไปลง 38–90% โดยไม่แตะต้องไฟล์หลักฐานใน .verify/*.log Shell output compression via rtk: Condenses routine command output by 38–90% while keeping .verify/*.log untouched.
  • ค้นหาผ่านกราฟ AST ด้วย codegraph & ast-grep: รู้จุดเรียกใช้ฟังก์ชัน (Callers/Callees) ทันทีโดยไม่ต้องไล่ grep ทั้งโปรเจกต์ Structural AST navigation via codegraph & ast-grep: Instant caller/callee blast-radius checks without blind file reads.
  • จำสาเหตุและวิธีแก้บั๊กด้วย projectmem: บันทึกสิ่งที่เคยลองแล้วไม่เวิร์กและวิธีแก้ที่ผ่านแล้วไว้รายโปรเจกต์ Persistent issue memory via projectmem: Tracks root causes, failed attempts, and verified fixes per repository.

คำสั่งใช้งานประจำวัน Everyday Commands

ควบคุมทุกอย่างผ่านคำสั่งเดียว devguard (พิมพ์ใน Terminal แค่ devg แล้วกด <Tab> ได้ทันที) Manage everything from a single CLI command: devguard.

Command การทำงานDescription
devguard เปิดเมนูแบบ Interactive เลือกคำสั่งด้วยปุ่มลูกศรOpen the interactive terminal menu
devguard status ดูตารางสถานะการเชื่อมต่อของทุก Agent และเครื่องมือในเครื่องShow the overview matrix of agents, rules, skills, and tools
devguard doctor [--fix] ตรวจสุขภาพ 7 จุดเสี่ยง (คราบปลั๊กอินเก่า, symlink, MCP, เวอร์ชัน) และซ่อมอัตโนมัติด้วย --fixAudit 7 failure modes and auto-repair with --fix
devguard stats [-p | -d] วัดผลการประหยัด Token (rtk, projectmem), ขนาดกราฟ codegraph และอัตราการ Verify ผ่าน (.verify/*.log)Measure token savings, AST graph coverage, and .verify/*.log pass rates
devguard select เลือกเปิด/ปิด Agents และเครื่องมือแบบกด SpacebarInteractively enable or disable agents and components
devguard update ดึงเวอร์ชันล่าสุด อัปเกรดเครื่องมือทั้งหมด และซิงก์การตั้งค่าใหม่Pull latest updates, upgrade tools, and re-apply configuration
devguard init [--all] ตั้งค่าโปรเจกต์ปัจจุบัน หรือทุกโปรเจกต์ใน ~/Developer ทันทีInitialize the current repo or all repos under ~/Developer
devguard uninstall [--purge] ถอดการเชื่อมต่อคืนสภาพเดิมทุกไบต์ (ใส่ --purge เพื่อลบ CLI ที่ระบบติดตั้งให้ด้วย)Cleanly unwire everything and restore original config files

🔄 ตั้งค่าโปรเจกต์ให้อัตโนมัติZero-Touch Repo Setup

ทุก Git Repo ใน ~/Developer จะถูกเพิ่ม .verify/ ลง .gitignore และสร้างดัชนี codegraph + projectmem อัตโนมัติเมื่อคุณ cd เข้าโฟลเดอร์ หรือผ่านการสแกนเบื้องหลังทุก 30 นาที Repos under ~/Developer are automatically indexed when you cd into them in zsh, start Claude Code, or via a lightweight 30-minute launchd scan.

🩺 ซ่อมแซมตัวเองได้ (Self-Healing)Self-Healing Doctor

devguard doctor --fix ตรวจจับและเก็บกวาดปลั๊กอินที่ตีกัน (เช่น tokless, caveman, ponytail), ย้ายไฟล์ MCP ให้ถูกตำแหน่ง และสำรองไฟล์เดิมไว้ที่ ~/.agent-kit-backup/ เสมอ devguard doctor --fix detects and cleans conflicting plugins, fixes broken symlinks, migrates MCP paths, and backs up every modified file.

📊 วัดผลได้จริง (Real Telemetry)Verifiable ROI Metrics

ไม่มีการคูณตัวเลขสมมติ devguard stats วัดจากจำนวน Token ที่ rtk ย่อจริง, จำนวนบั๊กที่บันทึกใน projectmem และอัตราการรันผ่านจริงจากไฟล์ .verify/*.log No fake multipliers. devguard stats reports real token savings from rtk, recorded fixes in projectmem, and actual pass rates from .verify/*.log.
