devguard

devguard คือระบบควบคุมมาตรฐานการทำงานแบบต้องมีหลักฐานจริง (verified-dev) ผสานกับชุดเครื่องมือประหยัด Token ที่ล็อกเวอร์ชันเสถียรไว้ให้ ติดตั้งเพียงครั้งเดียวแล้วแชร์ทั้งกฎการทำงานและเครื่องมือทั้งหมดร่วมกันได้ทุก Agent: Claude Code, VS Code (Copilot), Google Antigravity, Cursor, OpenCode, Codex CLI และ Gemini CLI

แนวคิดการออกแบบ 2 ชั้น (Two-Layer Architecture) (1) ชั้นวิธีทำงาน (Working Mode): บังคับให้ AI เลือก Playbook ตามประเภทงาน, อยู่ในโหมดอ่านอย่างเดียวเมื่อถามคำถาม และต้องมีหลักฐานการรันจริงก่อนบอกว่า "เสร็จ"
(2) ชั้นประหยัด Token (Components & Companion Tools): ย่อผลลัพธ์คำสั่งใน Terminal และสร้างกราฟ AST ของโค้ดโดยไม่ตัดทอนไฟล์หลักฐานใน .verify/*.log

การติดตั้ง (Installation)

ปิดโปรแกรม Claude Code, VS Code และ Antigravity ก่อนรันคำสั่ง (เพื่อไม่ให้โปรแกรมเขียนทับไฟล์ตั้งค่าตอนปิด) จากนั้นรันคำสั่งเดียวใน Terminal:

sh — ติดตั้งในคำสั่งเดียว (macOS / Linux) 
curl -fsSL https://raw.githubusercontent.com/Burapa-J/devguard/main/bootstrap.sh | bash

สคริปต์ bootstrap.sh จะทำงานดังนี้โดยอัตโนมัติ:

  1. ติดตั้งเครื่องมือพื้นฐานที่ยังขาดผ่าน Homebrew (git, jq, python3, node, xcbeautify, ast-grep, shellcheck)
  2. Clone โปรเจกต์ไว้ที่ ~/.local/share/agent-kit/src (หรืออัปเดตของเดิมหากเคยติดตั้งแล้ว)
  3. รัน ./install.sh ด้วยค่าเริ่มต้นที่แนะนำ: ติดตั้งกฎหลัก, สกิล verified-dev, hook เตือนหลัง compact, เชื่อม codegraph + projectmem + rtk และเปิดการตั้งค่าโปรเจกต์อัตโนมัติใน ~/Developer
  4. เพิ่ม ~/.local/bin เข้า PATH ใน ~/.zshrc

ตัวเลือกการติดตั้งเพิ่มเติม

sh 
./install.sh --dry-run                                        # ดูสิ่งที่จะเปลี่ยนโดยไม่แก้ไขไฟล์จริง
./install.sh --with=codegraph,projectmem,rtk,context-mode     # เปิดใช้งาน context-mode เพิ่มเติม
./install.sh --targets=claude,vscode,antigravity              # เลือกติดตั้งเฉพาะบาง Agent
./install.sh --auto-project=~/Developer,~/Work                # กำหนดโฟลเดอร์ที่ให้ตั้งค่าโปรเจกต์อัตโนมัติ

เริ่มต้นอย่างรวดเร็ว (Quickstart)

หลังติดตั้งเสร็จ ให้เปิด Terminal แท็บใหม่ แล้วตรวจสอบสถานะด้วยคำสั่ง:

sh 
devguard status        # ดูตารางสถานะการเชื่อมต่อของทุก Agent และเครื่องมือ
devguard doctor        # ตรวจสุขภาพการติดตั้งทั้ง 8 ข้อ
devguard stats         # ดูสถิติการประหยัด Token และอัตราการ Verify ผ่าน
devguard gate init     # ใน repo: สร้าง .devguard/checks และติดตั้งด่านตอน commit/push

1. วิธีทำงาน (verified-dev)

พัฒนาต่อยอดจากแนวคิดของ pstack (Lauren Tan), Karpathy Guidelines และ Ponytail ประกอบด้วยกฎหลักขนาดสั้น 9 บรรทัด (rules/core.md) และสกิลเชิงลึก (skills/verified-dev/SKILL.md):

  • เลือก Playbook ตามประเภทงาน: แยกขั้นตอนชัดเจนสำหรับ Investigation, Bug fix, Feature, Refactor, Perf issue และ Prompt / LLM pipeline
  • โหมดอ่านอย่างเดียวเมื่อถามคำถามหรือรีวิวแผน: เมื่อคุณถามคำถามหรือปรึกษาทางเลือก AI จะไม่แก้ไขไฟล์ใดๆ จนกว่าคุณจะสั่งให้ลงมือ
  • ห้ามเดาจาก --help หรือชื่อไฟล์: ก่อนอธิบายการทำงานของระบบหรือเสนอแผนออกแบบ AI ต้องอ่านโค้ดจริงทั้งขาอ่าน, ขาเขียน, การจัดการ ID/State และกรณีชนกัน พร้อมอ้างอิง file:line เสมอ
  • เช็คผู้เรียกใช้ทั้งหมด (Sibling-Caller Check): ตรวจสอบทุกจุดที่เรียกใช้ฟังก์ชันผ่าน codegraph_explore ก่อนแก้ เพื่อให้จุดที่เกี่ยวข้องไม่พังตาม
  • ต้องมีหลักฐานจากการรันจริงเสมอ: การ build ผ่านไม่ใช่ข้อพิสูจน์ ทุกครั้งที่บอกว่า "เสร็จ" ต้องอ่านไฟล์ .verify/<name>.log และสรุปใบเสร็จตรวจสอบสั้นๆ 1 บรรทัด (คำสั่ง, exit code, ผลลัพธ์หลัก และลิงก์ไฟล์ log) โดยแปะ log เต็มเฉพาะเมื่อพัง
  • ทุกข้อเท็จจริงต้องบอกที่มา: ลงท้ายด้วย (read file:line), (ran: คำสั่ง → exit N), (inferred) หรือ (unchecked) หาหลักฐานก่อนตอบ และถ้าคำตอบเปลี่ยนต้องบอกว่าเปลี่ยนเพราะหลักฐานใด
  • Pre-mortem ก่อนทำฟีเจอร์: ตาราง "อะไรจะพัง / เกิดเมื่อไร / ออกแบบกันอย่างไร / test ที่พิสูจน์" แถวที่ไม่มี test ต้องรายงานเป็นความเสี่ยงที่เปิดอยู่
  • พิสูจน์ว่า test ล้มได้: test ใหม่จะนับได้ก็ต่อเมื่อเคยล้มด้วยเหตุผลที่ถูกต้อง (ก่อนแก้ หรือเมื่อถอดการป้องกันออก)
  • ด่าน "เสร็จ": ถ้า repo มี .devguard/checks ต้องผ่าน devguard check ก่อนบอกว่าเสร็จ และห้ามข้าม hook ด้วย --no-verify

2. เครื่องมือที่ติดตั้งและดูแลให้ (Components & Companion Tools)

ติดตั้งตรงจากต้นทาง (Upstream) ด้วยเวอร์ชันที่ล็อกไว้ชัดเจน และไม่ใช้ local prompt proxy ที่ทำให้การเชื่อมต่อสะดุด

ชื่อเครื่องมือ ประเภท หน้าที่ แพ็กเกจต้นทาง ค่าเริ่มต้น
codegraph MCP Component สร้างกราฟ AST ค้นหา Symbol และจุดเรียกใช้ (codegraph_explore) npm @colbymchenry/codegraph@1.6.2 เปิด (On)
projectmem MCP Component ความจำรายโปรเจกต์และระดับเครื่อง (บั๊ก, สิ่งที่ลองแล้ว, วิธีแก้, การตัดสินใจ) พร้อมซิงค์ข้ามเครื่องแบบ CRDT ผ่าน iCloud Drive อัตโนมัติ PyPI projectmem==0.3.4 (แยก venv) เปิด (On)
rtk Hook / Plugin บีบอัดผลลัพธ์คำสั่งใน Terminal ลง 38–90% ก่อนส่งเข้า Context Homebrew rtk (1.1.0+) เปิด (On)
context-mode MCP Component รันคำสั่งใน Sandbox และทำดัชนีค้นหาสำหรับ Output ขนาดใหญ่ (Node ≥ 22.5) npm context-mode@1.0.169 เลือกเปิดเอง
ast-grep Companion CLI ค้นหาและแก้โค้ดตามโครงสร้าง Tree-sitter AST แบบหลายบรรทัด Homebrew ast-grep ติดตั้งพร้อมใช้
xcbeautify Companion CLI ย่อ log ของ xcodebuild ให้เหลือเฉพาะสรุปและบรรทัดที่เกิดปัญหา Homebrew xcbeautify ติดตั้งพร้อมใช้
shellcheck Companion CLI ตรวจ shell script แบบ static; kit ใช้ตรวจตัวเองทุก commit Homebrew shellcheck ติดตั้งพร้อมใช้
gitleaks Gate check สแกน secret ในไฟล์ที่ stage ไว้ เพิ่มเข้า .devguard/checks ของ repo ที่ต้องการ Homebrew gitleaks เลือกใช้ราย repo

คำสั่ง CLI ทั้งหมด

คำสั่ง การทำงาน
devguard เปิดเมนูแบบ Interactive เลือกคำสั่งด้วยปุ่มลูกศร
devguard status แสดงตารางสรุปสิ่งที่ติดตั้งและเชื่อมต่อไว้ในทุก Agent
devguard doctor [--fix] ตรวจสุขภาพ 8 จุดเสี่ยง และใส่ --fix เพื่อซ่อมแซมอัตโนมัติ
devguard stats [options] ดูสถิติประหยัด Token, ขนาดกราฟ AST และอัตราการ Verify ผ่าน (-p โปรเจกต์นี้, -d รายวัน, --dashboard, --reset)
devguard sync [--quiet] ซิงค์ความจำของ projectmem ข้ามเครื่องผ่าน iCloud Drive แบบ Append-Only CRDT
devguard sync --check อ่านอย่างเดียว: ทุกเครื่องมี event ตรงกันหรือยัง แยกตามโปรเจกต์ (in-sync, diverged, single, incomplete)
devguard check [commit|push] รัน .devguard/checks ของ repo (ด่าน "เสร็จ") ล้มแล้ว exit 1
devguard gate init|install|uninstall สร้างไฟล์ checks ตัวอย่าง และ/หรือ ติดตั้ง/ถอด hook pre-commit และ pre-push
devguard review [--with claude|agy|gemini] [--base REF] ให้ model อีกค่ายรีวิวงานแบบอ่านอย่างเดียว ผลอยู่ที่ .verify/review-*.md
devguard eval run|compare วัดความถูกต้อง, tag ที่มา และการกลับคำเมื่อถูกกดดัน เทียบผลสองรอบได้
devguard select เลือกเปิด/ปิด Agents และเครื่องมือแบบ Interactive
devguard update ดึงโค้ดเวอร์ชันล่าสุด อัปเกรดเครื่องมือทั้งหมด และซิงก์การตั้งค่าใหม่
devguard init [--all] ตั้งค่าโปรเจกต์ปัจจุบัน หรือทุกโปรเจกต์ในโฟลเดอร์อัตโนมัติ
devguard skip สร้างไฟล์ .agent-kit-skip เพื่อยกเว้นโปรเจกต์ปัจจุบันจากการตั้งค่าอัตโนมัติ
devguard uninstall [--purge] ถอดการเชื่อมต่อคืนค่าเดิมทุกไฟล์ (ใส่ --purge เพื่อลบ CLI ที่ระบบติดตั้งให้ด้วย)

การเก็บหลักฐานด้วย agent-verify

เพื่อไม่ให้ rtk ตัดทอนบรรทัดสำคัญของการทดสอบ คำสั่งตรวจสอบจะรันผ่าน agent-verify ซึ่งบันทึกผลลัพธ์เต็มลงไฟล์ .verify/<name>.log พร้อมชี้เลขบรรทัดที่เกิด error (errors_at=L...):

sh 
agent-verify unit-tests -- swift test
# ผลลัพธ์: agent-verify[unit-tests] exit=0 lines=42 log=.verify/unit-tests.log

agent-verify build-check -- xcodebuild test -scheme MyApp -destination 'platform=macOS'
# ผลลัพธ์: agent-verify[build-check] exit=65 lines=184 errors_at=L92,L141 log=.verify/build-check.log

ด่าน "เสร็จ" (.devguard/checks)

กฎเป็นแค่การขอให้ agent ตรวจงาน แต่ด่านนี้ตรวจให้จริงไม่ว่า model ไหนเขียนโค้ด แต่ละ repo เขียนคำสั่งตรวจจริงไว้ในไฟล์ .devguard/checks (commit เข้า repo) บรรทัดละหนึ่ง check:

.devguard/checks 
commit build:   swift build                                    # ทุก commit: ต้องเร็ว
push   test:    swift test                                     # ก่อน push: suite เต็ม
commit secrets: gitleaks git --staged --redact --no-banner .   # เลือกใส่: กัน secret หลุดเข้า commit

devguard gate init สร้างไฟล์ตัวอย่างและติดตั้ง hook pre-commit / pre-push ส่วน devguard check ใช้รันเองได้ทุกเมื่อ ทุก check รันผ่าน agent-verify ถ้าล้มจะแสดงบรรทัดเดียว พร้อม log เต็มที่ .verify/gate-<name>.log

  • ไม่ทับ hook ที่ไม่ได้เขียนเอง (จะบอกบรรทัดที่ต้องเพิ่มให้แทน) และใช้กับ worktree กับ core.hooksPath ได้
  • ถ้าย้าย kit ไปที่อื่น จะปล่อย commit ผ่านพร้อมคำเตือน เพื่อไม่ให้ทุก repo ถูกบล็อก
  • เตือนเมื่อ commit แก้ไฟล์ .devguard/checks และถ้าไฟล์เขียนผิดรูปแบบจะล้มพร้อมบอกเลขบรรทัด
  • รัน check ด้วย SIGPIPE ค่าปกติและ Python แบบ isolated ผลจึงเหมือนรันใน terminal
  • ข้อจำกัด: ตรวจ working tree ทั้งหมด ไม่ใช่เฉพาะส่วนที่ stage และ git commit --no-verify ยังข้ามได้ (กฎหลักห้ามไว้)

รีวิวข้ามค่าย (devguard review)

model แต่ละค่ายจับปัญหาได้ต่างกัน devguard review ส่งงาน (งานที่ยังไม่ commit รวมไฟล์ใหม่, commit ล่าสุด หรือทั้งช่วงด้วย --base REF) ให้ model อีกค่ายรีวิวแบบอ่านอย่างเดียวตาม rubric: บั๊ก, จุดที่อาจพัง, test ที่ผ่านแม้ไม่มีการแก้ และคำกล่าวอ้างที่โค้ดไม่รองรับ แสดงผลบรรทัดเดียว (verdict, จำนวนข้อ, path ของรายงาน) และเก็บรายงานไว้ที่ .verify/review-<เวลา>-<ผู้รีวิว>-<pid>.md

sh 
devguard review --with agy        # Claude เขียน: ให้ Gemini (ผ่าน Antigravity) รีวิว
devguard review --with claude     # Gemini เขียน: ให้ Claude รีวิว
devguard review --base main       # รีวิวทั้ง branch

เลือกค่ายที่ไม่ได้เขียนโค้ดนั้น Gemini CLI ปฏิเสธบัญชีส่วนตัวแล้ว ฝั่ง Gemini จึงใช้ agy แทน CLI ของผู้รีวิวต้อง login ใน terminal หนึ่งครั้ง ถ้ายังไม่ได้ login จะมีคำแนะนำบอก ผลรีวิวเป็นแค่ข้อสงสัย ต้องเปิดโค้ดยืนยันทีละข้อ

วัดผล agent (devguard eval)

การแก้กฎจะยังเป็นแค่สมมติฐานจนกว่าจะวัดผล ชุดคำถามเป็น JSON บรรทัดละข้อ มี prompt, regex expect, regex reject (ไม่บังคับ) และ pushback (ไม่บังคับ) สำหรับถามกดดันต่อในบทสนทนาเดิม:

sh 
devguard eval run .devguard/evals/kit.jsonl --with agy --reps 3 --label before
# ...แก้กฎ...
devguard eval run .devguard/evals/kit.jsonl --with agy --reps 3 --label after
devguard eval compare .verify/eval-before-*.json .verify/eval-after-*.json

รายงานผลรายข้อ: คำตอบแรกถูกหรือไม่, จำนวน tag ที่มาต่อคำตอบ และกลับคำบ่อยแค่ไหนเมื่อถูกกดดัน

การตรวจสุขภาพและซ่อมแซมตัวเอง (devguard doctor)

คำสั่ง devguard doctor ตรวจสอบ 8 จุดเสี่ยงของระบบ และซ่อมให้อัตโนมัติเมื่อใส่ --fix:

  1. คราบการติดตั้ง tokless เดิม (รวมถึงล้าง ANTHROPIC_BASE_URL proxy ที่ค้างใน ~/.claude/settings.json)
  2. Symlink ขาดหรือชื่อเก่าที่ค้างอยู่ใน ~/.local/bin
  3. ปลั๊กอินที่ทำงานซ้ำซ้อนหรือตีกัน (caveman, ponytail, cavecrew)
  4. ตำแหน่งไฟล์ MCP ของแต่ละ Agent
  5. ปลั๊กอินและ Hook ของ RTK สำหรับ Google Antigravity
  6. ความตรงกันของบล็อกกฎในไฟล์ของแต่ละ Agent เทียบกับ rules/core.md
  7. เวอร์ชันของ CLI ทั้งหมดและเครื่องมือเสริม (ast-grep, xcbeautify, shellcheck)
  8. memory sync ข้ามเครื่อง: hook .pth ชี้ไปที่ kit นี้, มี iCloud hub และไม่มี projectmem MCP ที่ยังรันโค้ด sync เก่า (ให้ปิดเปิด agent ใหม่ --fix ไม่ปิด process ให้)

การตั้งค่าโปรเจกต์อัตโนมัติ และซิงค์ความจำข้ามเครื่อง

ทุก Git repository ภายใต้ ~/Developer (ลึก 1–2 ชั้น) จะถูกตั้งค่าให้อัตโนมัติผ่าน 3 ช่องทาง: ตอนเปิด Claude Code, ตอนสั่ง cd เข้าโฟลเดอร์ใน zsh และการสแกนเบื้องหลังของ launchd ทุก 30 นาที โดยตรวจซ่อมทั้ง .gitignore, .codegraph/, .projectmem/config.toml, .git/hooks/post-commit และทะเบียนใน ~/.projectmem/projects.json

ซิงค์ความจำข้ามเครื่องผ่าน iCloud Drive (Multi-Mac CRDT Sync): เมื่อเปิดใช้งาน iCloud Drive ระบบจะซิงค์ความจำของ projectmem ข้ามเครื่องอัตโนมัติผ่าน ~/Library/Mobile Documents/com~apple~CloudDocs/devguard-sync/:

  • แยกไฟล์ตามเครื่อง (Per-Device Node Files): แต่ละเครื่องเขียนลงไฟล์ของตัวเอง (nodes/<device_id>.jsonl, docs/<device_id>-PROJECT_MAP.md, docs/<device_id>-plan.md, global/nodes/<device_id>.json) จึงไม่เกิดไฟล์ซ้ำของ iCloud
  • จับคู่โปรเจกต์ด้วย Git Root Commit (root-<sha12>): แม้ตั้งชื่อโฟลเดอร์คนละชื่อกันในแต่ละเครื่อง ระบบก็จับคู่เข้าถังความจำเดียวกันอัตโนมัติ
  • แก้เลข Issue ชนกันขณะออฟไลน์: เรียงลำดับตามเวลาพร้อมผูก parent_issue_key และอัปเดต .projectmem/.current_issue ให้เองโดยข้อมูลไม่ปนกัน
  • ซิงค์แบบ Real-time โดยไม่ต้องคอยรันเอง: ทำงานอัตโนมัติทุกครั้งที่ MCP อ่านหรือเขียนความจำ (ผ่าน .pth hook) รวมถึงตอน cd, ตอน launchd สแกน หรือสั่ง devguard sync
  • ไม่ทำ event หายระหว่าง sync: การเขียน events.jsonl ใช้ lock ร่วมกัน event ที่เพิ่มเข้ามาระหว่าง sync จึงไม่หาย
  • ตรวจว่า sync ตรงกันหรือยัง: devguard sync --check เทียบไฟล์ของทุกเครื่องทีละโปรเจกต์ และบอกชื่อเครื่องที่ยังขาด event ส่วน devguard status แสดงยอดรวม repo ที่ยังไม่มี commit และไม่มี remote จะไม่ถูก sync จนกว่าจะ commit ครั้งแรก เพื่อไม่ให้ repo คนละตัวที่ชื่อโฟลเดอร์ซ้ำกันรวมความจำกัน

การถอนการติดตั้ง (Uninstalling)

ทุกไฟล์ที่ถูกแก้ไขจะมีสำเนาสำรองอยู่ที่ ~/.agent-kit-backup/<เวลา>/ (เก็บชุดสำรองล่าสุดไว้สูงสุด 10 ชุดโดยอัตโนมัติ) และการสั่ง uninstall จะคืนสภาพไฟล์เดิมกลับมาทุกไบต์:

sh 
devguard uninstall --dry-run     # ดูสิ่งที่จะถูกลบโดยไม่ลบจริง
devguard uninstall               # ถอดกฎ, skill, hook และ MCP ออก (เก็บ CLI ของเครื่องมือไว้)
devguard uninstall --purge       # ลบ CLI ที่ devguard ติดตั้งให้ด้วย
